Local Pipeline Guide / Candidate Review Area

Source Intelligence Workbench

Read-only visibility for the SEC ingestion pipeline and relationship evidence contract. Curated production edges, SEC-backed production edges, and candidate preview records are labeled separately before anything becomes production graph data.

READ ONLY LOCAL TERMINAL COMMANDS CANDIDATES NOT GRAPH DATA EVIDENCE LABELS NO BROWSER SCRIPT RUNNER
Relationship Evidence States
Curated production

Loaded from data/connections.json. If source URLs are missing, the graph labels that evidence as pending.

SEC-backed production

Promoted only after local preview, manual review, and validation. SEC-backed status requires SEC filing provenance or SEC source URLs.

Candidate / preview

Shown as preview overlays only. Candidate records are not production claims until promoted through the safety gate.

Missing source

Rendered as evidence pending with source warnings. The UI does not infer partnership/customer claims from missing fields.

Source aging

Uses verified dates or candidate filing dates only. Missing dates stay labeled as no verified date, not outdated.

Host category

Source host badges are derived from URL hosts and paths, including SEC, IR, partner/customer, research, candidate-only, and other URLs.

Tiered Evidence Policy
VERIFIED visibility

SEC, official company, or strong source-backed production relationship evidence.

STRONG fast-track

Obvious public competitor or ecosystem overlap. Safe graph visibility, not official partnership proof.

CONTEXT enrichment

OpenAlex, topic overlap, research context, or weak ecosystem hints. Never relationship proof.

REVIEW manual only

Ambiguous, weak, candidate-only, conflicting, or unresolved records stay review-first.

How to Run Locally

Open PowerShell, cd to the repo root, then run one command at a time. The repo root contains index.html, data/, and scripts/.

SEC USER-AGENT

Network-enabled SEC commands need a real contact string. The user-agent is not an account and does not email you; it identifies the script politely to the SEC. Example: "Name User@Email.com".

Recommended Workflow

This is the bulk-first local path for generating SEC candidates safely.

Browser displays commands only.
Scheduled Preview -> Reviewed Job Plan -> Bulk Candidate Generation -> Review Artifact Refresh -> Promotion Planner -> Promotion Preview -> Manual Promotion -> Validation
1. Scheduled Preview 
python scripts/sec_scheduled_run_preview.py --schedule-id weekly_mega_cap_core_preview --include-commit-plan
2. Bulk Candidate Generation 
python scripts/sec_bulk_pipeline_run.py --tickers AAPL,MSFT,NVDA,AMZN,GOOGL,META,AMD,INTC,AVGO,JPM,GS,BLK,XOM,CVX,UNH,LLY,GE,CAT --forms 10-K,10-Q,8-K --limit 10 --allow-network --user-agent "Name User@Email.com" --write-candidates --force

Preferred candidate generation path. Use tickers from the approved ticker/CIK universe or reviewed jobs; output remains candidate-only, and promotion still requires preview, manual promotion, and validation.

3. Promotion Preview 
python scripts/sec_candidate_promotion_preview.py
3A. Reviewer Triage Artifacts 
python scripts/sec_candidate_triage.py --write --force

Generates review-only queue, summary, overlap, and checklist artifacts. It reads production data only for comparison and writes no production graph data.

3B. Review Artifact Refresh 
python scripts/review_artifact_refresh.py --write --force

Refreshes triage, preflight, source coverage, source governance, OpenAlex cache-only enrichment, validation, and a review pipeline summary. It does not run promotion.

3B-LIVE. Bounded Live Refresh 
python scripts/live_refresh_orchestrator.py --write --force --max-requests 32

Writes refresh status under data/refresh/, refreshes review artifacts, and keeps provider network access disabled unless explicit network flags and local configuration are present.

3C. OpenAlex Enrichment 
python scripts/openalex_enrichment.py --write --force --max-requests 24 --max-entities 20

Generates review-only OpenAlex ecosystem, topic, institution, and cluster hints. Add --allow-network only when local budget and cache settings are acceptable.

3D. Source Registry Governance 
python scripts/source_registry_governance.py --write --force --sync-registry

Refreshes reviewer-owned registry, universe readiness, corridor maintenance, graph scaling, and OpenAlex safety summaries. It performs zero production writes.

3E. Promotion Planner Report 
python scripts/promotion_planner_report.py --write --force

Builds the review-only planner artifact with readiness scoring, reviewer-state summaries, batch comparisons, and graph-impact simulation. It performs zero production writes and cannot approve promotion.

3F. Reviewed Production Expansion 
python scripts/production_company_expansion.py --dry-run
python scripts/production_company_expansion.py --write
python scripts/validate_data.py

Uses an explicit reviewer-approved production expansion manifest. It promotes identity-backed companies and only manifest-listed source-backed edges; it does not generate relationships.

4. Manual Promotion 
python scripts/sec_candidate_promote.py
5. Validation 
python scripts/validate_data.py

Scheduled Preview

Previews cadence, the next job command, candidate generation, policy gate, validation, and optional commit plan. It does not execute scheduled jobs.

Reviewed Job Runner

Optional manifest path for reviewed jobs such as mega_cap_core or batch_1_multi_sector. It delegates reviewed bulk runs; the main path remains bulk candidate generation.

Bulk Runner

Generates review-only SEC relationship candidates from approved ticker/CIK mappings. Network access and candidate writes require explicit flags.

Safety Notes
  • No backend or browser script runner is added.
  • The browser does not call SEC directly.
  • Candidate files are review-only and not production graph data.
  • Broader coverage comes from approved mappings and reviewed jobs.
  • Production promotion stays manual, previewed, policy-gated, and validated.
  • Reviewed production expansion is allowed only from an explicit approval manifest.
